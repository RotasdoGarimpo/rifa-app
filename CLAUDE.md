# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Bun + Turborepo monorepo scaffolded with Better-T-Stack (`bts.jsonc`). Elysia HTTP server, oRPC for type-safe APIs, Prisma ORM over PostgreSQL (`pg` driver adapter), Next.js 16 PWA frontend (React 19, Tailwind v4, TanStack Query), Biome for lint/format, Lefthook for pre-commit hooks.

## Commands

```bash
bun install              # install deps (runs `prisma generate` via postinstall)
bun run dev              # start everything in dev mode (server on :3333, web on :3000)
bun run dev:server       # start only apps/server (bun --hot)
bun run dev:web          # start only apps/web (next dev --port 3000)
bun run build            # turbo build (server built with tsdown → dist/)
bun run check-types      # tsc -b across workspaces
bun run check            # Biome lint + format with --write (whole repo)

# Database (all run inside packages/db)
bun run db:start         # start local Postgres via docker compose (detached; db:watch for foreground)
bun run db:stop          # stop the Postgres container (db:down to remove it)
bun run db:push          # prisma db push
bun run db:generate      # prisma generate (client output: packages/db/prisma/generated/)
bun run db:migrate       # prisma migrate dev
bun run db:studio        # Prisma Studio
```

There is no test setup in this repo.

Pre-commit (Lefthook) runs `biome check --write` on staged files and re-stages fixes.

## Architecture

Workspace layout (Bun workspaces + a `catalog:` in root package.json for shared dep versions; new workspace packages should reference catalog versions where possible):

- `apps/web` — Next.js 16 App Router PWA (`next dev --port 3000`, typed routes, React Compiler enabled). PWA manifest is generated by `src/app/manifest.ts` (icons in `public/favicon/`). oRPC client lives in `src/utils/orpc.ts`: an `RPCLink` pointing at `${NEXT_PUBLIC_SERVER_URL}/rpc` wrapped with TanStack Query utils (`orpc.healthCheck.queryOptions()` style), fully typed against `AppRouterClient` from `@rifa-app/api`. Path alias `@/*` → `src/*`. Env in `apps/web/.env`, validated via `@rifa-app/env/web`. **`next.config.ts` rewrites `/rpc/*` and `/api/auth/*` to `SERVER_ORIGIN`** — the browser only ever talks to this origin, which is what keeps the admin session cookie first-party (see the auth notes below). `/api/uploadthing` is deliberately not rewritten; that handler is local.
- `packages/ui` — shared React component kit (`@rifa-app/ui`), shadcn-style components over base-ui + Tailwind v4. Exports `./components/*`, `./lib/*`, `./globals.css`, `./postcss.config`. Add new shadcn components here, not in `apps/web`.
- `apps/server` — Elysia entry point (`src/index.ts`). Mounts Better Auth's fetch handler at `/api/auth/*`, then the oRPC router twice: `RPCHandler` at `/rpc*` (RPC protocol, for typed clients) and `OpenAPIHandler` at `/api-reference*` (OpenAPI + reference UI via `OpenAPIReferencePlugin`). All three use `parse: "none"` so the handler gets the raw request. Builds with tsdown, which inlines all `@rifa-app/*` packages (`noExternal`).
- `packages/api` — oRPC layer. `src/index.ts` defines `o = os.$context<Context>()`, `publicProcedure`, and `protectedProcedure` (the single `requireAdmin` middleware — the only place authorization is enforced). `src/routers/index.ts` exports `appRouter` (plain object of procedures) plus the `AppRouter`/`AppRouterClient` types. `src/context.ts` resolves `context.session` via `auth.api.getSession`; procedures depend on that and never on how it was produced.
- `packages/auth` — Better Auth. `./server` exports the `auth` instance (Prisma adapter, username plugin, email/password with `disableSignUp: true`, 12h sessions with a 5-minute cookie cache, rate limiting always on) plus a `createAuth()` factory the seed script uses to open sign-up for one call. `./client` exports the browser `authClient` and imports nothing from the server half, so `apps/web` never pulls in Prisma or a server secret.
- `packages/db` — Prisma. Multi-file schema dir `prisma/schema/` — `schema.prisma` for the raffle domain, `auth.prisma` for Better Auth's `user`/`session`/`account`/`verification` tables (regenerate with `bunx @better-auth/cli@latest generate --config packages/auth/src/server.ts`, then strip the generator/datasource blocks it emits). `prisma.config.ts` points at the **directory**, not a single file. Generated client is committed-adjacent at `prisma/generated/` (uses the new `prisma-client` generator with `runtime = "bun"` — which is why auth lives in the Bun process and not in Next). `src/index.ts` exports a default `PrismaClient` wired through the `PrismaPg` driver adapter — the datasource block has no `url`; the connection URL comes from `DATABASE_URL` at runtime and via `prisma.config.ts` for CLI commands. Local Postgres runs from `packages/db/docker-compose.yml` (postgres:18 on :5432, db/user `rifa-app`/`postgres`).
- `packages/env` — `@t3-oss/env-*` validated env: `@rifa-app/env/server` (`DATABASE_URL`, `CORS_ORIGIN`, `PORT`, `ADMIN_WHATSAPP`, `PIX_KEY`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `NODE_ENV`) and `@rifa-app/env/web` (`NEXT_PUBLIC_SERVER_URL`, `SERVER_ORIGIN`, `UPLOADTHING_TOKEN`). Import env from here, not `process.env`.
- `packages/config` — shared `tsconfig.base.json` (strict, bundler resolution, `verbatimModuleSyntax`, noUnused*).

Env vars live in per-app files: `apps/server/.env` and `apps/web/.env` (both gitignored). `packages/db/prisma.config.ts` loads `../../apps/server/.env` for Prisma CLI commands; `packages/env/src/server.ts` uses `dotenv/config` and `web.ts` relies on Next's own loading.

### Admin auth

One admin account, no public sign-up, no email provider (so no verification and no password reset). Create or rotate it with `bun run -F server seed:admin <usuario> '<senha>' [--force]` — the script builds an auth instance with sign-up enabled and goes through the ordinary sign-up endpoint, so the password hash can never drift from what sign-in expects. The account's email is synthetic (`<usuario>@rifa.local`); sign-in goes through the username plugin.

The two URL vars are the part that trips people up. `NEXT_PUBLIC_SERVER_URL` is the **web app's own** origin (both the oRPC and auth clients target it), `SERVER_ORIGIN` is `apps/server`, and `BETTER_AUTH_URL` on the server must equal the web origin because that is the `Origin` the rewrite forwards. The whole point is that `apps/web` and `apps/server` sit on different domains in production, which would make the session cookie third-party — Safari blocks those outright.

All workspace packages export raw TypeScript source (`./src/*.ts`) with no build step; only `apps/server` builds/bundles.

To add an API endpoint: add a procedure to `appRouter` in `packages/api/src/routers/index.ts` (input/output validated with Zod v4). It is automatically exposed on both `/rpc` and the OpenAPI surface.

## Conventions

- Biome is the formatter/linter: tab indentation, double quotes, organized imports. Run `bun run check` rather than fixing style by hand.
- ESM everywhere (`"type": "module"`); use Bun APIs/types (`@types/bun`).
