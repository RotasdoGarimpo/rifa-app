# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Bun + Turborepo monorepo scaffolded with Better-T-Stack (`bts.jsonc`). Elysia HTTP server, oRPC for type-safe APIs, Prisma ORM over PostgreSQL (`pg` driver adapter), Next.js 16 PWA frontend (React 19, Tailwind v4, TanStack Query), Biome for lint/format, Lefthook for pre-commit hooks.

## Commands

```bash
bun install              # install deps (runs `prisma generate` via postinstall)
bun run dev              # start everything in dev mode (server on :3000, web on :3001)
bun run dev:server       # start only apps/server (bun --hot)
bun run dev:web          # start only apps/web (next dev --port 3001)
bun run build            # turbo build (server built with tsdown → dist/)
bun run check-types      # tsc -b across workspaces
bun run check            # Biome lint + format with --write (whole repo)

# Database (all run inside packages/db)
bun run db:start         # start local Postgres via docker compose (detached; db:watch for foreground)
bun run db:stop          # stop the Postgres container (db:down to remove it)
bun run db:push          # prisma db push
bun run db:generate      # prisma generate (client output: packages/db/prisma/generated/)
bun run db:migrate       # prisma migrate dev
bun run db:studio        # Prisma Studio
```

There is no test setup in this repo.

Pre-commit (Lefthook) runs `biome check --write` on staged files and re-stages fixes.

## Architecture

Workspace layout (Bun workspaces + a `catalog:` in root package.json for shared dep versions; new workspace packages should reference catalog versions where possible):

- `apps/web` — Next.js 16 App Router PWA (`next dev --port 3001`, typed routes, React Compiler enabled). PWA manifest is generated by `src/app/manifest.ts` (icons in `public/favicon/`). oRPC client lives in `src/utils/orpc.ts`: an `RPCLink` pointing at `${NEXT_PUBLIC_SERVER_URL}/rpc` wrapped with TanStack Query utils (`orpc.healthCheck.queryOptions()` style), fully typed against `AppRouterClient` from `@rifa-app/api`. Path alias `@/*` → `src/*`. Env in `apps/web/.env` (`NEXT_PUBLIC_SERVER_URL`), validated via `@rifa-app/env/web`.
- `packages/ui` — shared React component kit (`@rifa-app/ui`), shadcn-style components over base-ui + Tailwind v4. Exports `./components/*`, `./lib/*`, `./globals.css`, `./postcss.config`. Add new shadcn components here, not in `apps/web`.
- `apps/server` — Elysia entry point (`src/index.ts`). Mounts the oRPC router twice: `RPCHandler` at `/rpc*` (RPC protocol, for typed clients) and `OpenAPIHandler` at `/api-reference*` (OpenAPI + reference UI via `OpenAPIReferencePlugin`). Both routes use `parse: "none"` so oRPC handles the raw request. Builds with tsdown, which inlines all `@rifa-app/*` packages (`noExternal`).
- `packages/api` — oRPC layer. `src/index.ts` defines `o = os.$context<Context>()` and `publicProcedure`; `src/routers/index.ts` exports `appRouter` (plain object of procedures) plus the `AppRouter`/`AppRouterClient` types. `src/context.ts` builds the per-request context from the Elysia context — `auth`/`session` are currently stubbed to `null` (no auth configured).
- `packages/db` — Prisma. Schema lives in `prisma/schema/schema.prisma` (multi-file schema dir, configured via `prisma.config.ts`). Generated client is committed-adjacent at `prisma/generated/` (uses the new `prisma-client` generator with `runtime = "bun"`). `src/index.ts` exports a default `PrismaClient` wired through the `PrismaPg` driver adapter — the datasource block has no `url`; the connection URL comes from `DATABASE_URL` at runtime and via `prisma.config.ts` for CLI commands. Local Postgres runs from `packages/db/docker-compose.yml` (postgres:18 on :5432, db/user `rifa-app`/`postgres`).
- `packages/env` — `@t3-oss/env-*` validated env: `@rifa-app/env/server` (`DATABASE_URL`, `CORS_ORIGIN`, `NODE_ENV`) and `@rifa-app/env/web` (`NEXT_PUBLIC_SERVER_URL`). Import env from here, not `process.env`.
- `packages/config` — shared `tsconfig.base.json` (strict, bundler resolution, `verbatimModuleSyntax`, noUnused*).

Env vars live in `apps/server/.env` — note that `packages/db/prisma.config.ts` loads that same file via a relative path, so Prisma CLI commands read the server's `.env`.

All workspace packages export raw TypeScript source (`./src/*.ts`) with no build step; only `apps/server` builds/bundles.

To add an API endpoint: add a procedure to `appRouter` in `packages/api/src/routers/index.ts` (input/output validated with Zod v4). It is automatically exposed on both `/rpc` and the OpenAPI surface.

## Conventions

- Biome is the formatter/linter: tab indentation, double quotes, organized imports. Run `bun run check` rather than fixing style by hand.
- ESM everywhere (`"type": "module"`); use Bun APIs/types (`@types/bun`).
